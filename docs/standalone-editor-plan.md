# 独立流程编辑器：技术选型、命令行与 JSON 契约

> 2026-11-06 · 提议方案，尚未实现。
>
> 当前成果已先提交为 `77d97a2`（可视化编辑器设计检查点）。本文不意味着已有编辑器二进制、JSON 执行器或跨平台运行验证。
>
> 当前应用仍是 `app/ahk/D4Box.ahk` 单进程、INI 配方。本文实施后，编辑器成为独立进程；Windows 主程序仍统一管理游戏输入、热键与运行诊断。界面沿用 v0.2 的深色方案，不重新设计颜色。

## 1. 结论与责任边界

推荐 **Qt 6 + Qt Quick/QML + 小型 C++17 后端 + CMake**，同一源码分别构建 macOS 与 Windows 版本。先做覆盖层技术验证，再冻结所用稳定 Qt 小版本与依赖；不追随在线文档的滚动版本号。

```text
AHK 主程序                          独立 D4BoxEditor
  列出/选择配置 ──文件路径启动──────→ 编辑 JSON、点位、步骤、背包
  管理热键                          截图预览 / 桌面覆盖
  编辑期间暂停游戏输入              校验、撤销、保存
       ↑                                  │
       └──────── 本地配置 JSON ←───────────┘
       │
  独立校验 → 冻结运行快照 → 安全执行 → 只读 Debug
```

- 编辑器不依赖 AHK 安装，不发送游戏点击、不执行配方、不读取游戏内存。
- 业务数据通过 JSON 文件交接，不把 AHK 全局变量、INI 分隔字符串或进程句柄写入协议。
- 热键、当前选中方案、运行锁、真实扫描队列、日志属于主程序，不写进可分享配方。
- 运行时 Debug 仍属于主程序，只显示点位与背包编号；编辑器的只读预览不冒充实时游戏识别。
- 同仓库 `app/editor` 与 `app/ahk` 分模块维护，不新增 submodule；协议与测试样例独立存放。
- 文件协议解耦不等于没有安全协作：编辑覆盖层出现时，正在运行的 AHK 宏必须暂停，见第 8 节。

## 2. 为什么优先 Qt，而不是 WebView 编辑器

本项目关键难点不是表单，而是 **全客户区透明绘制、局部鼠标命中、连续拖动、多窗口焦点和 DPI 坐标转换**。

| 方案 | 适用性与取舍 |
| --- | --- |
| **Qt Quick + C++，推荐** | QML 做点位、格线、面板与主题；C++ 负责文件、坐标、原生窗口与平台适配。Qt 提供透明窗口、窗口输入标志和高 DPI API，适合作为原生覆盖层的验证起点。[1][2][3] |
| Tauri + 前端框架 | 可用作备选，但 `setIgnoreCursorEvents` 是窗口级能力，不会自动生成“空白穿透、点位接收”的原生命中区域；还需要验证或补原生适配，不能只靠 CSS 完成。[5] |
| Electron | 可做界面，但官方明确说明透明区域不会因此自动点击穿透；不能把透明网页当成完整覆盖层实现。本项目不以它作为首选。[6] |
| 继续 AHK GUI | 能复用现有 Windows 代码，但不解决用户当前需要的 Mac 本地编辑器。 |

### 独立程序不等于一个物理文件

第一版目标是一个独立可启动应用，而不是强求零依赖单文件：

- macOS：`D4BoxEditor.app`，内部含可从终端调用的 `Contents/MacOS/D4BoxEditor`。
- Windows：`D4BoxEditor.exe` 与必要的 Qt 库、插件组成发布目录/安装包。
- Qt 动态部署需携带实际使用的库、平台插件和 QML 模块；静态打包是另外的构建与许可评估事项，不作为首版承诺。[4]
- 分别产出 Mac 与 Windows 构建，不是同一个二进制在两个系统通用。Windows 包和真实游戏仍在 Windows 验证。
- 发布前核对所选 Qt 模块及第三方组件许可；不改动已有 D4KeyHelp 许可和来源声明。[4]

## 3. 两种模式，共用一个编辑会话

### 3.1 截图模式：Mac 首选调试闭环

通过 `--background IMAGE` 直接载入本地截图作为底图。不要求先用系统图片预览器打开，也不把图片预览器窗口位置当成游戏坐标。

1. 图片等比例显示，可铺满视口、缩放和平移；编辑层覆盖整张有效底图，仍采用顶栏和默认隐藏的步骤面板。
2. 首次选择图片中的**游戏客户区**，剔除系统标题栏、黑边等；不把此前设计图用过的裁剪高度写死。
3. 拖动点位、调整 3×11 背包、编辑步骤，均修改同一个文档模型。
4. 所有几何先映射回图片中的客户区，再保存归一化位置；缩放、留白、Retina 显示比例不进入配方坐标。
5. 保存、关闭、重开，几何位置与步骤内容应保持一致；用校验命令检查结构与静态运行前提。
6. 读取本地图片不使用屏幕捕获或合成输入；首版不因图片模式主动请求屏幕录制或辅助控制权限。
7. 可预览点位和格线；候选编号若来自测试数据必须明确标为样例，不能声称截图外的背包在实时更新。

底图路径、完整截图、图片元数据、面板坐标和个人路径只留在本地编辑器状态，不写进分享 JSON，不提交私人截图。

### 3.2 覆盖模式：用户提出的“图片在下、透明层在上”也支持

默认无 `--background` 时进入覆盖模式，`--overlay` 可显式指定。

- Mac 可以先打开截图，再从终端启动覆盖模式，用于验证实际桌面穿透与拖拽。需要手动确认截图的有效客户区，图片窗口移动后重新校准；不承诺自动跟踪第三方图片查看器。
- Windows 从主程序启动时传递临时目标窗口句柄，编辑器贴合其客户区；句柄失效、最小化或窗口状态不匹配时暂停覆盖并提示，不退回猜测屏幕坐标。
- 没有目标窗口时，先选择显示器与参考客户区。不能只按当前显示器尺寸就标记“游戏已校准”。
- Mac 的桌面覆盖仅验证编辑交互；真实游戏窗口、截图干净度、Windows 混合 DPI、无边框全屏和焦点必须另外测试。
- 第一阶段不承诺独占全屏、HDR、远程桌面与所有系统权限组合。

### 3.3 覆盖层不能只是一张透明大窗口

建议拆成：

1. **绘制窗口**：覆盖整个客户区，显示点位/网格，整体不接收鼠标输入。
2. **交互窗口/区域**：仅点位拖柄、背包边框、8 个控制点接收输入；不能用完整背包内部矩形截获游戏操作。
3. **顶栏与步骤工具窗**：独立输入区域；步骤面板默认隐藏，可打开、拖动、关闭，关闭不丢修改。

QML 的透明颜色或不处理 MouseArea 事件不等于向其他进程透传。Qt 的 `WindowTransparentForInput` 可用于整窗不接收输入；`QWindow::setMask` 文档把区域描述为窗口系统提示，不能直接承诺所有平台/后端效果相同。[1][2]

先验证掩码/原生命中区域；若不稳定，用只包围可交互对象的小工具窗口替代。Mac 的 AppKit 与 Windows 的 Win32 适配集中在平台层，避免分散到业务组件。

拖动开始后必须持续捕获鼠标，路径穿过原穿透区仍不中断；不能在每帧按“鼠标是否位于图标”开关整窗穿透。拖动时工具栏/面板避让，放下后不得重新挡住该点。

## 4. 命令行规则

以下命令均是**拟定接口，当前仓库尚无该二进制**。

```text
D4BoxEditor [PATH] [--new] [--background IMAGE | --overlay]
            [--screen INDEX | --target-window HANDLE] [--lang zh-CN|en-US]
D4BoxEditor validate PATH [--for-run] [--format human|json]
D4BoxEditor --help
D4BoxEditor --version
```

### 4.1 位置参数 PATH

| 输入 | 行为 |
| --- | --- |
| 不传 PATH | 立即创建内存中的未命名配置并进入编辑；不自动打开上次配置、不立即写文件；首次保存选择文件位置。 |
| 已存在目录 | 扫描该目录的配置，按确定顺序选择第一个可加载配置进入编辑；同时可切换同目录其他配置。 |
| 已存在配置 JSON 文件 | 精确打开该文件并选中；配置目录设为其父目录，可切换兄弟配置。 |
| 空目录或只有无关文件 | 在该目录建立未保存新配置；首次保存默认落在此目录，确认前不创建文件。 |
| `--new` 加目录 | 明确在指定目录中新建，不打开第一份旧配置；`--new` 不加目录与无参新建相同。 |
| 不存在路径 | 明确报错，不猜测是文件还是目录，不把拼错的文件名当成新建。 |
| `--new` 加文件 | 参数冲突，报错；复制/另存通过界面操作，不把新建解释为覆盖。 |

“第一个”的定义：按文件名做 Unicode NFC 规范化后、不区分大小写排序；同键再用原文件名的码点序排序。不要使用文件系统枚举顺序、修改时间或上次选中记录覆盖此规则。

目录只扫描直接子文件，不递归。默认新文件扩展名为 `.d4workflow.json`，也接受内容符合协议的普通 `.json` 文件：

- 具有 `kind: "d4box.workflow"` 的合法结构文档进入列表；完整的草稿也可成为首个选中项，不要求可执行。
- 其他 JSON 文档不当成配方。
- 本工具专用后缀但损坏的文件、或声明本工具 kind 但结构错误的文件，显示为错误项并提示文件名，不覆盖、不当成可运行项。
- 显式传入损坏文件时，报错并保持其内容，不悄悄切换到同目录别的文件。
- 全部候选损坏时显示错误列表，允许用户显式新建；不能显示成“空目录”。
- 同目录两个配置 ID 相同则标记冲突，不任意挑一份运行；“复制配置”必须生成新 ID。

### 4.2 可选参数

| 参数 | 约定 |
| --- | --- |
| `--background IMAGE` | 载入本地图片并隐含截图模式；图片不存在/不受支持则报错，不降级为桌面覆盖。 |
| `--overlay` | 显式桌面覆盖，与 `--background` 互斥。 |
| `--screen INDEX` | 覆盖模式的显示器选择，索引为本次启动显示器列表中的 0 基编号；不写入配置；不存在则报错。 |
| `--target-window HANDLE` | Windows 主程序集成使用，指定客户区来源；与 `--screen` 及截图模式互斥。在 Mac 使用时报不支持，不忽略。句柄只用于此次会话。 |
| `--lang zh-CN/en-US` | 覆盖本次 UI 语言；不改变配置的内容语言，不混入业务 JSON。 |
| `--` | 终止选项解析；以连字符开头的文件名放在它后面。命名为 `validate` 的目录用 `./validate` 避免与子命令冲突。 |

相对路径以启动进程的工作目录解析；文件、目录和图片的相对路径分别相对该目录，不相对彼此。主程序一律传绝对路径，按目标进程参数规则正确引用空格/中文，不用未经转义的 shell 拼接。

文件目标的符号链接先解析并显示真实路径，其兄弟列表以真实父目录为准；目录内不跟随指向目录外的文件链接，避免保存意外改写外部目标。只读文件允许查看，保存时提供另存为，失败不得显示为已保存。

### 4.3 示例

```sh
# 新建未保存配置；默认透明覆盖模式
D4BoxEditor

# 从一个目录选中第一份配置
D4BoxEditor "./workflows"

# 精确编辑现有文件；可切换同目录配置
D4BoxEditor "./workflows/嬗变.d4workflow.json"

# 在指定目录新建；截图模式用于 Mac 日常开发
D4BoxEditor "./workflows" --new --background "./cube.png"

# 编辑已有配置并在截图上回看位置
D4BoxEditor "./workflows/嬗变.d4workflow.json" --background "./cube.png"

# 不开 GUI 的静态校验：这不是游戏实测
D4BoxEditor validate "./workflows/嬗变.d4workflow.json" --for-run --format json
```

Mac 开发时以上程序名换为构建出的应用内可执行路径，例如 `./build/editor/D4BoxEditor.app/Contents/MacOS/D4BoxEditor`；实际输出位置由后续构建预设固定，不承诺此路径现在存在。

### 4.4 退出与多开

- GUI `0`：正常关闭，包括确认放弃修改；不代表保存成功或当前配置可运行。
- `2`：参数/路径错误；`3`：配置解析或校验失败；`4`：I/O 或写入失败；`5`：平台模式不支持或初始化失败。
- 保存失败先保留窗口与修改，让用户重试/另存，不自动退出。如果用户确认放弃后正常退出，主程序也不能以退出码推断曾经保存。
- `validate` 默认只检查文档结构和基础引用，允许合法草稿；`--for-run` 再检查静态运行前提，不尝试找到游戏或发送输入。
- `validate` 目录时逐份报告；有错误或没有任何配方时不返回成功。有不相关 JSON 可忽略并在统计中注明；专用后缀损坏文档必须报错。JSON 输出走 stdout，诊断日志走 stderr。
- 第一版不做跨进程“把新请求转交旧窗口”的单实例服务，保证主程序能跟踪实际子进程。对同一真实文件加写锁，重复打开只能只读/定位既有窗口，不能成为第二个写入者。
- 不同文件可有独立编辑会话；真实桌面覆盖同一目标只允许一个，文件锁与覆盖会话锁分开。

## 5. JSON 契约：一份文件是一份配置

固定 UTF-8 JSON，无注释、无尾逗号；独立维护版本化 JSON Schema 和语义规则。Qt 的 JSON 解析不应被误当成完整 Schema/业务校验，实现时需显式增加两层验证。

| 字段 | 含义 |
| --- | --- |
| `kind` | 固定 `d4box.workflow`，用于目录识别。 |
| `schemaVersion` | 首版 1；不支持的版本拒绝执行，编辑器只能只读查看或显式迁移。 |
| `id`、`revision` | 稳定 UUID、每次成功保存递增的修订号。复制生成新 ID；重命名不改 ID。 |
| `name`、`description` | 可读说明；不依赖文件名或 UI 列表位置。 |
| `status` | `draft` / `ready`；只是保存状态，执行器必须重新验证，不能信任一个 ready 字符串。 |
| `requires` | 必需能力名，如 `mouse.click.v1`；执行器不支持就禁用，不静默跳过动作。 |
| `source` | `hover_item` / `inventory_once` / `preloaded`，以及起始品质筛选、数量上限、排除格。 |
| `points`、`layouts` | 稳定点位定义与每个布局的几何；背包固定 rows=3、columns=11；客户区基准尺寸、UI 缩放说明和校准状态。 |
| `checks` | 检查规则、位置引用、稳定采样、超时；区分“当前存在”与“动作后发生转换”。 |
| `steps` | 有序数组，稳定 ID、名称、通用动作、按钮、目标引用、起始品质条件、间隔和结果检查。 |
| `limits` | 单轮件数、总超时等上限；必须有界，不支持无限循环。 |
| `provenance` | 可选模板来源/旧配置来源标记；不保存个人路径。 |

首版动作白名单为 `click`、`wait`、`check`；“选择嬗变”“接受”等只是步骤名称，不再作为执行器专用函数。`click` 支持 left/right，引用固定点或 `current_item` 动态目标。

未知字段、未知动作/检查规则、悬空引用不能在保存时被悄悄丢弃或在执行时忽略。扩展须更新版本/能力声明与验证器；首版不提供脚本、shell 命令、任意插件或网络加载。

### 5.2 坐标与验证级别

- 固定点保存 `{x, y}`，背包边界保存 `{x, y, width, height}`，均相对**有效游戏客户区**归一化；不保存桌面绝对坐标。
- 边界位于 `[0,1]`；矩形宽高必须为正且整体在区内；未校准用 null，不用 `(0,0)` 假装有效。
- 最后映射点击像素时约定 `floor(u * W)`，再限定到 `0..W-1`，Y 同理；客户区物理屏幕原点只在输入层最后加一次。所有实现使用同一组边界测试样例。
- Qt 界面使用逻辑像素，图片缓冲区是图像像素；两者必须经过显式变换，不能给已经转换过的位置再次乘 DPI。[3]
- 同比例缩放不等于自动识图。宽高比、UI 缩放或布局不匹配时拒绝静默执行，要求校准。
- 三层验证分开：① JSON/Schema；② ID 引用、路径展开、布局、检查点和有限循环等静态语义；③ Windows 游戏窗口和当前画面的运行前置检查。
- `ready` / `validate --for-run` 仅代表前两层通过，不代表真实游戏验证成功。任何游戏验证记录放本机诊断信息，不随分享配置转移为“可信”。

## 6. 保存、切换与单文件语义

为遵循“一份 JSON 代表这份配置”，首版建议简化旧设计中的发布副本机制：**文件是当前已保存版本，不暗中另存一份仍可运行的旧发布内容**。这是一项需确认的交互简化，而非现有代码行为。

- 打开后在内存编辑，未保存修改不影响磁盘文件。
- “保存方案”及编辑器获得焦点时的 Ctrl/Cmd+S 使用同一规则：完整校验通过保存为 ready；不完整可明确选择保存为 draft。
- 现有 ready 方案若要保存为 draft，必须提示“保存后此配置的运行入口将停用”，可选择**另存为草稿**保留原可运行文件；不静默降级。
- 主程序显示草稿但禁用运行；原热键绑定可保留为不可运行状态，触发时给出原因，不偷偷回退到旧版执行。
- 新建首次保存选择目录和文件名；有明确目录入参就预填该目录，无参则弹保存对话框，不静默写入工作目录或程序安装目录。
- 同目录切换、关闭窗口、退出编辑均检查 dirty：保存 / 放弃 / 继续。保存失败或取消位置选择则不切换、不关闭。
- 自动恢复记录与正式 JSON 隔离，且不进入主程序扫描列表；恢复记录不是可运行副本。
- 先完整校验，再通过临时文件写入并原子替换。采用 QSaveFile，保持 direct-write fallback 关闭；无法原子保存就报错，不能直接截断旧文件。[7]
- 保存前复查原文件内容哈希与 revision；外部已修改时提供重载/另存，不自动覆盖。成功后才清除 dirty、更新 revision。
- 主程序运行中冻结配置快照。外部保存不热改正在运行的步骤；发现新错误或文件失效时禁用下次启动，不清空正在执行的快照。经主程序进入编辑则先停止运行，见下一节。

若坚持“保存草稿但运行旧发布版”，需另做显式草稿/发布双版本协议，不能把这两种语义混在一个文件里悄悄实现。首版暂不采用。

## 7. 现有 AHK 不是直接换文件后缀就能接入

当前 `CubeProfiles.ahk` 读取 INI，普通动作统一左键、装入隐式右键，旧 `manual` 表示已手动装入。新 JSON 需要明确适配：

1. 增加经过许可审查的 JSON 解析器、版本/能力检查、目录扫描与配置状态。
2. 读取 points/layouts/checks/steps，解析引用，展开起始品质路线，生成不可变执行计划。
3. 左/右键成为通用动作；装入已转为显式步骤时移除该路径的隐式装入，避免点击两次。
4. `hover_item` 是新增来源；旧 `manual` 只能迁为 `preloaded`，不能改为鼠标所在格。
5. 背包扫描改为读取布局；客户区坐标统一映射；剥离 `isAutoTransmuting` 与只读扫描的耦合。
6. JSON 执行端重复执行语义校验及运行前置检查，不靠编辑器的 ready 标签保证安全。
7. 保留旧 INI 读取及当前行为作为明确的兼容路径，迁移时备份。新 JSON 不能丢字段转回旧 9 字段字符串来冒充完整支持。
8. 内置嬗变迁为数据模板；保留原始品质分支、各处坐标与延时，未有依据的结果检查标为缺失，不编造“已验证”。

首版明确不支持任意表达式、无限循环、自动 OCR 滚动搜索；这些可作为后续版本化能力扩展，不假定选了跨平台 UI 框架就会自动具备。

## 8. 主程序启动编辑器与安全联动

建议流程：

1. GUI 选择配置 → “配置”；先拒绝重入或请求结束正在运行的任务，等待输入执行器确实空闲。
2. 暂停战斗宏、禁用流程运行热键、关闭主程序 Debug，并持有编辑会话锁；紧急停止仍有效。
3. 以参数数组语义启动编辑器，传配置文件绝对路径；Windows 游戏内编辑另传目标 HWND。新建则传配置目录和 `--new`。
4. 主程序跟踪实际子进程，编辑器切换同目录文件不结束会话、不释放编辑锁。
5. 配置目录发生变化后防抖重扫；退出编辑器、主 GUI 重新获得焦点和用户手动刷新时也重新扫描，不只依赖目录监听。临时文件、恢复记录、锁文件不作为配置。
6. 退出后重读并重新校验文件，更新列表；不凭退出码判断保存了哪份配置。正常退出/异常退出均不自动恢复战斗宏，不自动执行流程。

独立从终端启动的编辑器同样不能绕过安全约束：Windows 覆盖模式若 AHK 主程序正在运行，需通过小型本地会话协议协商“停止输入并进入编辑”；拿不到确认时只能退回截图编辑/拒绝覆盖，不能显示可点击拖柄后继续让宏点击游戏。

该协议只传会话开始/结束、存活和空闲确认，不传配方业务数据。具体采用命名管道/本地锁及进程句柄在 Windows 原型时确定；不能只设一个可能在崩溃后永久残留的布尔文件。主程序未运行时编辑器仍可独立使用，Mac 截图模式不要求有主程序。

运行时 Debug 留在 AHK，避免为纯观察常驻另一个编辑器进程。需要共享的是几何/识别规则与测试样例，不是把编辑器的窗口或实时扫描状态塞进 JSON。

## 9. 代码落点与交付顺序

建议结构（尚未创建）：

```text
app/editor/                    Qt 编辑器独立构建
  src/core/                    文档、目录、校验、保存、撤销
  src/platform/macos/          覆盖层、窗口、焦点、DPI 适配
  src/platform/windows/        同上；编辑安全会话
  qml/                         画布、顶栏、点位、背包、步骤面板
  tests/                       核心与交互回归
contracts/                     版本化 Schema、动作/检查语义说明
contracts/fixtures/            无私人数据的正反例、坐标映射与分支样例
app/ahk/                       原主程序及新增 JSON 适配
```

### 阶段 A：先做最小技术验证，不铺完整业务

Mac 验证透明层、穿透区、一个可拖点、背包控制点、顶栏/步骤工具窗、Retina 转换；Windows 尽早验证同一原型的无边框游戏覆盖、拖拽不误点、前后台和 DPI。任一关键输入模型不成立，先调整平台层，不把不可靠方案扩大到完整编辑器。

### 阶段 B：Mac 的完整数据编辑闭环

实现参数/目录、截图客户区标定、点位/背包/步骤编辑、撤销、保存/切换确认、JSON Schema 与无 GUI validate。使用现有深色主题；步骤面板默认隐藏，保留增删排序；无游戏输入功能。

### 阶段 C：Windows 集成与旧配置迁移

AHK 增加目录列表、启动编辑器、安全会话、JSON 编译适配、旧 INI 兼容、热键状态和运行时 Debug。使用模拟输入先回归红装/黄装顺序与取消，再做真实游戏验证。

### 验收门槛

- 无参、文件、目录、空目录、损坏文件、中文空格、只读文件、重复 ID、非法参数均有确定行为。
- 新建不写盘；放弃不留下空配置；保存失败不丢稿；切换有确认；同文件多开/外部修改不相互覆盖。
- 截图缩放/平移/裁剪和 Retina 后，保存重开位置一致；同一几何由编辑器和 AHK 测试样例得到相同点击像素/格中心。
- 全客户区每个点均可拖到；边框之外点击穿透；背包内部不误拦截；拖动到穿透区域不中断。
- 步骤面板默认隐藏，可打开/拖动/关闭，增删与撤销不产生悬空引用。
- 草稿不能执行；非法 ready、未知版本/能力/动作被执行器拒绝；仅时间等待不能代替必要结果检查。
- 保存不运行，编辑不点击，崩溃不自动恢复宏；外部启动也有安全联动。
- Debug 仅点位/背包/编号；干净画面采样不能把覆盖层误识别成物品或成功状态。
- Mac 静态校验、截图交互、Windows 模拟执行、真实游戏验证分别记录，不能互相代替。
