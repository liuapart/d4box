<a id="launch"></a>
## 1. 安装与启动

**提示需要 VS 或 Qt？** 这是旧独立 editor 的开发启动路径。当前主程序发行版直接运行 EXE，不需要 VS、Qt 或 AHK；下载[主程序发行版](installation.md#download)。

**源码脚本提示找不到 AutoHotkey？** `-AhkPath` 必须指向本机实际存在的 v2 解释器，示例路径不会自动安装软件。先用 `Test-Path -LiteralPath '实际的解释器路径'` 检查，再按[源码启动指引](installation.md#source)放置工具或修正参数。

**配置无法保存？** 检查 EXE 所在目录是否可写、是否仍在 ZIP 预览中运行。先解压到固定可写目录再启动。

<a id="workflow-key"></a>
## 2. F3 没反应，或没有执行新流程

依次检查：

1. **列表绑定**：主界面该键对应的“执行流程”是什么？编辑器选中“新建流程1”不等于 F3 已改绑。用“编辑绑定”指定，或在编辑器“保存并设为默认流程”。
2. **保存与草稿**：是否保存内容？是否提示缺少就绪标记、点击执行、末尾检测或有效区域节点？草稿可以保存，但未满足条件不会运行。
3. **前台和初始画面**：暗黑 IV 是否在前台、正确的魔盒／配方面板是否已打开？仅在主窗口按 F3 不是开始游戏流程的方式。
4. **采集或已有任务**：截图采集期间不能启动；已有流程运行时按另一个流程键是取消，不是切换执行。
5. **绑定错误**：主界面是否提示绑定不可用、引用丢失或冲突？修复后保存；宏 F1 与流程 Ctrl+F1 也冲突。
6. **坐标基准**：内置主屏流程要求游戏客户区铺满主屏。自定义窗口模式需要客户区坐标及自己的标定。

保留报错原文，它通常比“按键没反应”更能指出缺少的条件。

<a id="capture"></a>
## 3. 点击截图后主界面隐藏，但没有冻结画面

区域库只采集前台暗黑 IV 客户区。确认游戏已启动，并在 3 秒倒计时结束前切回游戏；其他软件或桌面不能代替游戏窗口进行常规采集。

正确过程是：点击按钮 → 窗口隐藏并倒计时 → 游戏截图冻结 → 在冻结图上拖矩形 → 返回局部预览。你不需要手动截图或把图片粘贴回来。

如果目标面板被聊天框、悬浮窗等遮挡，先关闭遮挡再重新采集。取消选区按 Esc。

<a id="detection"></a>
## 4. 面板已打开，但检测失败

| 检查顺序 | 要看什么 | 如何处理 |
| --- | --- | --- |
| 1. 测试时机 | 是在“面板出现时测试”，且倒计时结束时面板仍可见吗？ | 保持正确状态，重新测试 |
| 2. 画面尺寸与 DPI | 区域库显示的采集宽高和 DPI 是否对应当前游戏？ | 不同则重新采集、双向测试 |
| 3. 选区内容 | 模板是不是动画、物品名、数量、悬停按钮，或拍到了错误状态？ | 换固定标题／图标等独特特征 |
| 4. 遮挡与鼠标悬停 | 鼠标提示、悬浮层是否盖住或改变目标区域？ | 移开鼠标、关闭遮挡 |
| 5. 区域位置 | 面板偏移是否超过搜索余量？ | 优先固定布局，再考虑小幅增加余量 |
| 6. 颜色变化 | 相同画面仍有小幅色差？ | 小幅调整容差，每次都重做出现和关闭测试 |
| 7. UI 缩放／布局 | 客户区相同但游戏内部比例是否改变？ | 重新标定，不能靠同一张旧模板自动适配 |

“关闭测试失败”意味着面板没有出现时也匹配上了，尤其要排查大片公共背景，不能只提高容差直到出现测试通过。

单点颜色模式只检测一个像素；区域模式使用保存的整张模板在局部范围匹配。两者都不是文字识别，也没有相似度百分比参数。

<a id="node"></a>
## 5. 检测节点无法选择、失效或丢失

- 下拉框没有新区域：检查是否已采集、**两项测试都通过**并点击“保存区域”。草稿不会作为新可用节点提供。
- 改了容差后不能运行：这是测试证据失效，重新双向测试并保存。
- 提示模板不存在：核对 `.runtime\detection-regions` 内 BMP 与 `regions.ini` 是否配套恢复；不要只复制 INI。
- 改名是否需要逐个重选：不需要，引用使用稳定 ID。
- 删除被拒绝：先解除已保存流程或当前草稿对该区域的引用。

不要为了让流程继续而删除节点引用；先修复真正要检查的条件。

<a id="pointer"></a>
## 6. 右键 X/Y 不能编辑，鼠标比流程更早归位

这是“右键选择物品”的来源规则：单物品模式锁定启动时鼠标位置；背包模式取当前扫描格。该动作不需要填 X/Y，也不会随着后续鼠标移动而重新选目标。

普通左键动作仍需要各自坐标。可选接受的按钮位置与检测点／模板也是两回事，模板能识别不代表按钮位置已正确采集。

单物品模式在最后鼠标动作后尽早归位，后面仍可能在等待结果检测。观察当前步骤确认是否结束。失焦或失败发生在归位前时不会强行归位；背包流程不使用该归位逻辑。

**有弹窗却没有接受？** 检查检测是否稳定、超时是否覆盖弹窗出现时间，以及独立的接受按钮坐标。没有弹窗时跳过是预期行为，后面的必需结果检查仍应保留。

<a id="macro"></a>
## 7. 按键宏没有动作或一直暂停

先看主界面的状态，再确认当前宏配置至少有一行策略不是“禁用”，键位与游戏实际绑定一致。

- 切出游戏自动暂停：回游戏，观察是否恢复。
- Tab 手动暂停：需在游戏里用 Tab 继续，或停止后重新启动；仅切回游戏不解除手动暂停。
- 流程失败／取消后暂停：先确认游戏状态，再按需恢复宏。
- “维持BUFF”不符合预期：检查技能栏布局和状态条位置，必要时先用单行连点验证键位。

宏参数说明见[间隔与延迟](macros.md#timing)。当前主程序已经移除血球检测、辅助喝药等旧功能，旧 INI 的相关开关不会恢复这些功能。

<a id="display"></a>
## 8. 页面显示不全或文字重叠

记录显示器分辨率、Windows 缩放百分比、游戏客户区尺寸和 d4box 版本，截图保留完整窗口。把窗口移到可容纳它的显示器上检查；不要把裁剪掉的底部按钮当成已被移除。

若调整了 DPI、分辨率或游戏 UI 缩放来排查，已有检测模板和坐标要重新验证。发现布局问题可按下方模板反馈，附上完整窗口截图和缩放信息。

<a id="update"></a>
## 9. 更新失败或配置消失

**查询失败／超时／限流**：稍后重试，或从本仓库[发布页](https://github.com/liuapart/d4box/releases)手动下载。失败不等于已是最新版；旧 editor 版本不属于主程序更新。

**下载后配置不见**：最常见是从“下载”文件夹启动了另一份 EXE。数据跟随 EXE 所在目录。退出后回原目录启动，或按[迁移教程](updates-and-backup.md#migrate)完整复制配置。

**替换时文件被占用**：停止任务并完全退出程序，检查托盘中是否仍在运行，再替换 EXE。

<a id="report"></a>
## 10. 收集信息并反馈

游戏前台按 **Ctrl+Alt+F8** 打开窗口诊断。数据目录的 `.runtime\window-diagnostics.log` 和 `debugd4.log` 可用于定位窗口、检测与流程问题。
